# Cookbook

This page is the index of repeated tasks. Each row names the one canonical procedure and the check that shows it succeeded; the steps themselves live in the linked document, not here.

Add a page under this directory only when a procedure repeats, branches enough to need its own steps, and is not already maintained as a section of another document. A new page follows this contract: prerequisites, steps, verification, common failures. A procedure with one home stays there, and this table links to it.

| Task | Procedure | Verify |
| --- | --- | --- |
| Set up a deployment with its operator | [SETUP.md](../../SETUP.md): the agent asks one question at a time, shows one plan, then installs and configures | `scripts/dsh-superagent status` exits 0 with no setup problem ([SETUP.md](../../SETUP.md), Verify and hand over). Then a first request appears as a Ticket in Overview. |
| Install and start | [006 Deployment: Install](../006-deployment.md#install) and [Start and stop](../006-deployment.md#start-and-stop) | `start` waits up to one minute for the runtime to become ready or report a setup requirement; `status` exits 0. Exit codes 1, 2 and 3 say whether a restart, a failed part or setup is what needs attention. |
| Configure Sources, Policy, Execution and Prompts | [006 Deployment: Settings](../006-deployment.md#settings) | A save returns the new revision; re-read `GET settings`. A save that returns `restarting: true` restarts dsh-superagent — wait until `scripts/dsh-superagent status` exits 0 before the next request. |
| Add a named local environment or Source instance | [006 Deployment: Named local environments](<../006-deployment.md#named-local-environments>) and [SETUP.md](<../../SETUP.md>) | Reread the saved blocks and their revisions; check Source account readiness and fixed/Router choices. Confirm existing Tickets retain their recorded binding. New account/repository targets use new Source ids after durable use. |
| Upgrade a deployment | [006 Deployment: Upgrade](../006-deployment.md#upgrade) | Back up `<stateDir>/orchestrator.sqlite` first; `git pull && pnpm install && pnpm build`; restart and inspect `status`. Review prompt parts marked **Default updated**, and keep the worker and router presets in `cordis.patch.yml`. |
| Troubleshoot a deployment | [006 Deployment: Troubleshooting](../006-deployment.md#troubleshooting) | The `status` exit code classifies the problem; `errors` names each failed part and `setup` names what setup waits for. Fix the named cause, then check again. |
| Add a new Source | [008 Cookbook: Add a Source](../008-cookbook.md#add-a-source) | Follow its 11 steps and its checklist; test the kind as `tests/sources.spec.ts` tests the other Sources, then add the module to the Modules table in [007 Architecture](../007-architecture.md#modules) and its spec to the [Test catalog in Testing and verification](../testing.md#test-catalog). `tests/docs.spec.ts` checks that both indexes are complete. |
| Verify in a real isolated process, only with explicit approval | [007 Architecture: Reviewing a change in an isolated process](<../007-architecture.md#reviewing-a-change-in-an-isolated-process>) | Use a wholly new profile, process, state directory and port with synthetic data and stub CLIs. Leave production config, databases, workdirs and control files untouched; never restart an existing instance. |
| Maintain documentation | [docs/README.md](../README.md): its maintenance map says which documents a change updates | `./node_modules/.bin/vitest run tests/docs.spec.ts` checks structure, links, English prose and the indexes. Run the suites that [testing.md](../testing.md) names for the change. |
| Add or change interface copy | [Interface copy in two languages](../i18n/README.md) | `./node_modules/.bin/vitest run tests/locales.spec.ts`. When the same change edits the panel's markup or stylesheet, also run `tests/styles.spec.ts`. |
| Record a design decision | [Design notes](../../.agents/notes/README.md): a note records a long-lived choice and lives in `proposed/`, `implemented/` or `rejected/` by status | The note states context, decision, alternatives considered and consequences, and the code change refers to it. |

The commands, the environment and the full per-change check matrix are in [development](../development.md) and [testing](../testing.md). Documentation changes are described by [the documentation index](../README.md); deployment and source procedures also appear in [006 Deployment](../006-deployment.md) and [008 Cookbook](../008-cookbook.md).
